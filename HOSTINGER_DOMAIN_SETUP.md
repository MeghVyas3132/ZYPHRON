## 🔧 Key Components Set Up

### 1. **Nginx Reverse Proxy** (`infrastructure/nginx.conf`)
- Routes main domain to frontend
- Routes subdomains to backend
- Handles SSL/TLS encryption
- Redirects HTTP → HTTPS

### 2. **SSL Certificates** (`infrastructure/certs/`)
- Auto-generated by Let's Encrypt
- Covers: yourdomain.com, *.yourdomain.com, www.yourdomain.com
- Renewed automatically before expiry

### 3. **Docker Compose** (`docker-compose.yml`)
- Nginx container (ports 80, 443)
- Frontend container (port 3000)
- Backend container (port 8000)
- Database & cache containers

### 4. **Setup Scripts** (`scripts/`)
- `setup-domain.sh` - Interactive wizard
- `setup-ssl.sh` - Certificate generation

## 🚀 Quick Start Process

### Step 1: Gather Information

Find these values (you'll need them):

```bash
# Your public IP (will be given to Hostinger)
curl ifconfig.me
# Example output: 203.0.113.50

# Your local machine IP (for router)
ifconfig | grep "inet " | grep -v 127.0.0.1
# Example output: 192.168.1.100

# Your Hostinger domain
# Example: mydomain.com or mysite.hostinger.com
```

### Step 2: Configure Domain Setup

```bash
chmod +x scripts/setup-domain.sh
./scripts/setup-domain.sh
```

This asks for:
- Your domain name
- Your email for SSL
- Your public IP

### Step 3: Generate SSL Certificates

```bash
chmod +x scripts/setup-ssl.sh
./scripts/setup-ssl.sh
```

Certbot will:
- Validate your domain ownership
- Generate certificates
- Store them in `infrastructure/certs/`

### Step 4: Update Hostinger DNS

1. Log in to Hostinger control panel
2. Go to: **Domains** → **Your Domain** → **DNS**
3. Add/Update these A records:

| Name | Value | TTL |
|------|-------|-----|
| @ | YOUR_PUBLIC_IP | 3600 |
| www | YOUR_PUBLIC_IP | 3600 |
| * | YOUR_PUBLIC_IP | 3600 |

### Step 5: Configure Router Port Forwarding

1. Access your router (usually 192.168.1.1)
2. Find: **Port Forwarding** or **Virtual Server**
3. Add these rules:

| External Port | Protocol | Internal IP | Internal Port |
|---------------|----------|-------------|---------------|
| 80 | TCP | 192.168.x.x | 80 |
| 443 | TCP | 192.168.x.x | 443 |

(Use your local machine's IP from Step 1)

### Step 6: Start Docker Services

```bash
docker-compose up -d
```

Verify:
```bash
docker ps | grep zyphron
docker logs zyphron_nginx -f
```

### Step 7: Wait & Test

**Wait 24 hours** for DNS to propagate, then:

```bash
# Test from external network (phone hotspot, friend's wifi, etc.)
curl https://yourdomain.com
curl https://app1.yourdomain.com/api/v1/health
```

## 🌐 DNS Propagation

**What to expect:**
- DNS changes propagate in **24-48 hours**
- Different DNS servers might resolve at different times
- You can check status here: https://www.whatsmydns.net/?d=yourdomain.com

**During propagation:**
- Some users may reach your site, others won't
- This is normal and temporary
- After 48 hours, everyone can access it

## 🆘 Troubleshooting

### "DNS won't resolve"
- Wait 24-48 hours for propagation
- Check Hostinger DNS records are saved
- Verify: `nslookup yourdomain.com`

### "Connection refused"
- Check router port forwarding is configured
- Verify: `lsof -i :80,443` to see if ports are used
- Check firewall allows ports 80, 443

### "SSL certificate errors"
- Regenerate: `./scripts/setup-ssl.sh`
- Clear browser cache
- Wait 5 minutes for certificate to be issued

### "Nginx not starting"
- Check syntax: `docker exec zyphron_nginx nginx -t`
- View logs: `docker logs zyphron_nginx -f`
- Verify ports aren't in use: `lsof -i :80,443`

### "Backend not responding"
- Check backend logs: `docker logs zyphron_backend -f`
- Verify CORS settings in backend code
- Test directly: `curl http://localhost:8000/health`
